# @park-explorer/db — חבילת המסד

הסכימה, המיגרציות, הזריעה ויצרן החיבור של Park Explorer.

**החבילה אינה מכירה אף פריימוורק, ואינה קוראת את הסביבה.** אין בה NestJS, אין בה Express, ומחרוזת
החיבור מגיעה אליה כפרמטר. מי שמפעיל את התהליך הוא זה שקורא את `.env`. כך אותה חבילה משרתת
את השרת, את הזריעה ואת `drizzle-kit` בלי שאף אחד מהם יחייב את השני.

---

## מה מיוצא

שתי נקודות כניסה, מוגדרות ב-`exports` שבקובץ `package.json`:

```ts
import { createDatabase, type Database } from '@park-explorer/db';
```

```ts
import {
  parks,
  cities,
  regions,
  users,
  parkImages,
} from '@park-explorer/db/schema';
```

- `createDatabase(connectionString)` — מקים `Pool` של `pg` ומחזיר מופע Drizzle שהסכימה כבר רשומה בו.
- `Database` — טיפוס המופע. הצרכנים תלויים בו במקום להושיט יד לטיפוסים הפנימיים של Drizzle, כך ששינוי בספרייה נשאר בגבולות החבילה.
- `/schema` — אובייקטי הטבלאות והקשרים, לכתיבת שאילתות.

```
packages/db/

│   ├── index.ts                 יצרן החיבור + הטיפוס Database
│   ├── schema/

│   │   ├── regions.schema.ts
│   │   ├── cities.schema.ts
│   │   ├── users.schema.ts
│   │   ├── parks.schema.ts
│   │   ├── park-images.schema.ts
│   │   └── relations.ts         קשרי Drizzle — נפרדים מהגדרות הטבלאות
│   └── seed/
│       ├── seed.ts              סקריפט עצמאי
│       └── data/                מחוזות וערים, כטקסט
├── drizzle/                     קובצי SQL מיוצרים + מטא-דאטה. נכנסים ל-git
```

הקבצים בתיקייה `drizzle/` מיוצרים בידי הכלי אך **נשמרים ב-git**: הם ההיסטוריה של המסד, וגם מה
שמאפשר להריץ מיגרציות בסביבה שאין בה את הסכימה במקור.

## הסכימה

```
regions ──1:N──▶ cities ──1:N──▶ parks ──1:N──▶ park_images
                                   ▲
                                   └──1:N── users
```

| טבלה          | עמודות מפתח                                                                                                             | הערות                                         |
| ------------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `regions`     | `id`, `name`                                                                                                            | שם ייחודי גלובלית                             |
| `cities`      | `id`, `name`, `region_id`                                                                                               | שם ייחודי **בתוך מחוז**, לא ברמת המדינה       |
| `users`       | `id`, `name`, `email`, `password_hash`, `created_at`                                                                    | אימייל ייחודי                                 |
| `parks`       | `id`, `name`, `description`, `creator_id`, `city_id`, `opening_date`, `location`, `polygon`, `created_at`, `updated_at` | ראו למטה                                      |
| `park_images` | `id`, `park_id`, `image_url`, `created_at`                                                                              | הטבלה קיימת; אין לה עדיין שום שימוש באפליקציה |

כל המפתחות הראשיים הם `uuid` עם `defaultRandom()`.

### החלטות שכדאי להכיר

- **גאומטריה כ-JSONB, לא PostGIS.** השדה `location` הוא GeoJSON מסוג `Point`, והשדה `polygon` הוא `Polygon`. שניהם מוקלדים בעזרת `$type<>()` של Drizzle מול הטיפוסים של `@types/geojson` — כלומר ההקלדה היא בטיפוסים בלבד, והמסד רואה JSONB. **המשמעות: אין שאילתות מרחביות.** אי אפשר לשאול "מה בטווח חמישה קילומטרים" בלי לשנות את הטיפוס לעמודת PostGIS.
- **מדיניות מחיקה מכוונת.**
  - מחוז, עיר ומשתמש הם `restrict` — מחיקה שיש לה תלויות נכשלת, במקום למחוק בשקט.
  - התמונות הן `cascade` — הן נמחקות יחד עם הפארק, בידי המסד ובלי שהשרת יבקש.
- **חותמות זמן עם אזור זמן.** כל עמודות הזמן הן `timestamptz`, כלומר נקודה מוחלטת בציר הזמן.
- **העמודה `updated_at` מתעדכנת לבדה** — היא מוגדרת עם `$onUpdate` בסכימה, ולא בטריגר במסד.
- **הקשרים בקובץ נפרד.** הקובץ `relations.ts` מרכז את כל קשרי Drizzle, כדי שקובצי הטבלאות יישארו הצהרת מבנה ותו לא.

## שני חיבורים, ולא במקרה

| משתנה                   | סוג החיבור ב-Neon | מי משתמש                          |
| ----------------------- | ----------------- | --------------------------------- |
| `DATABASE_URL`          | pooled            | השרת בזמן ריצה, וסקריפט הזריעה    |
| `DATABASE_URL_UNPOOLED` | direct            | `drizzle-kit` — מיגרציות ו-Studio |

מיגרציות מריצות פקודות DDL וסביבות עבודה ארוכות. מאגר חיבורים יכול להגיש כל פקודה בחיבור אחר,
וזה בדיוק מה ששובר אותן. לכן ההפרדה, ולכן `drizzle.config.ts` דורש את המשתנה הישיר ומפיל את
עצמו מיד אם הוא חסר.

שני התהליכים העצמאיים בחבילה — קובץ התצורה וסקריפט הזריעה — טוענים בעצמם את הקובץ

```
../../.env
```

הנתיב יחסי לתיקיית העבודה, שהיא תיקיית החבילה הזו בין אם הפקודה הורצה מהשורש דרך Turborepo
ובין אם ישירות מכאן. הרצה מתיקייה אחרת לא תמצא את הקובץ.

## פקודות

מהשורש, דרך Turborepo:

```bash
npm run db:generate      # סכימה → קובץ SQL חדש בתיקיית drizzle
npm run db:migrate       # מריץ את המיגרציות שטרם רצו
npm run db:seed          # מחוזות וערים
npm run db:studio        # Drizzle Studio
```

מתוך `packages/db`, אותן פקודות זמינות ישירות, ובנוסף:

```bash
npm run build            # tsc -p tsconfig.build.json → dist/
npm run dev              # אותו דבר ב-watch
npm run check-types
npm run lint
```

### תהליך העבודה על שינוי סכימה

1. לערוך את קובץ הסכימה תחת `src/schema/`.
2. `npm run db:generate` — נוצר קובץ SQL חדש. **כדאי לקרוא אותו לפני שממשיכים.**
3. `npm run db:migrate` — הרצה מול המסד.
4. לוודא שהחבילה נבנתה מחדש, אחרת השרת ימשיך לראות את הסכימה הישנה.
5. אם השינוי נוגע לצורה שפרוצדורה מחזירה — להריץ `npm run trpc:generate` מהשורש.

## הזריעה

הסקריפט `src/seed/seed.ts` מכניס 4 מחוזות ו-14 ערים, מתוך `src/seed/data/`.

- הוא רץ תחת `ts-node`, על המקור. אינו דורש בנייה.
- הוא משתמש ב-`onConflictDoNothing`, ולכן **הרצה חוזרת בטוחה** ואינה מייצרת כפילויות.
- הוא קורא את המחוזות בחזרה מהמסד כדי למפות שם למזהה, ולכן אינו מניח דבר על סדר ההוספה.
- **הזריעה מכניסה נתוני ייחוס בלבד.** אין בה משתמשים ואין בה פארקים.

## נקודה שקל להיכשל בה

התיקייה `apps/api` צורכת את החבילה הזו **בנויה**: הערך של `main` הוא `./dist/index.js`.
מכאן ששינוי בקובץ סכימה אינו משפיע על השרת בזמן ריצה עד שהחבילה נבנית מחדש — בשונה משינוי
בקוד השרת עצמו, שהצופה קולט מיד.

תחת `npm run dev` מהשורש זה מטופל: הסקריפט `dev` של החבילה הוא `tsc --watch`.
אבל לפני שמסיקים ששינוי בסכימה "לא עושה כלום" — כדאי לוודא שהוא באמת קיים בתוך `dist`.
